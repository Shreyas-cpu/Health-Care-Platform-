Purpose: Patients and providers need a trustworthy booking and financial pipeline where slot reservation is concurrency-safe, payment capture is atomic, and cancellation refunds execute automatically according to platform policy.
Output: Schedule management APIs, slot generation engine, atomic booking service, Razorpay payment and refund handler, cancellation policy engine, and concurrency stress tests.
</objective>

<task type="locking">
  <files>backend/app/services/booking_service.py, backend/app/api/v1/bookings.py</files>
  <action>
    1. Implement atomic slot hold via Redis:
       - Acquire lock key `lock:doctor:{doctor_id}:slot:{slot_start_iso}` with TTL = 10 minutes.
       - If lock acquired, insert Appointment in `requested` state and set `payment_status = 'pending'`.
       - If lock fails, return HTTP 409 Conflict ("Slot is currently being booked by another patient").
    2. Database exclusion constraint prevents any overlapping confirmed appointment for the same doctor even if Redis lock were bypassed.
  </action>
  <verify>pytest backend/tests/test_atomic_booking.py -k "test_redis_locking" || true</verify>
</task>

<task type="payment">
  <files>backend/app/models/payment.py, backend/app/services/payment_gateway.py, backend/app/api/v1/payments.py</files>
  <action>
    1. Define PaymentTransaction model (appointment_id, gateway_order_id, gateway_payment_id, amount, currency, status, method, created_at).
    2. Integrate Razorpay API client:
       - `POST /api/v1/payments/create-order`: initiates Razorpay order for exact appointment fee.
       - `POST /api/v1/payments/webhook`: validates HMAC SHA256 signature from Razorpay.
    3. Atomic Capture (RUL-03):
       - Inside PostgreSQL transaction, update PaymentTransaction to `captured`, promote Appointment from `requested` to `confirmed`, and release Redis lock.
       - If payment fails or TTL expires, cancel Appointment (`cancelled`) and release slot lock.
  </action>
  <verify>pytest backend/tests/test_atomic_booking.py -k "test_payment_capture"</verify>
</task>

<task type="cancellation-engine">
  <files>backend/app/models/cancellation_policy.py, backend/app/schemas/cancellation.py, backend/app/services/cancellation_policy_engine.py, backend/app/api/v1/cancellations.py</files>
  <action>
    1. Define `CancellationPolicy` model/config:
       - `free_cancellation_window_hours`: Integer (default: 2)
       - `allow_late_cancellation`: Boolean (default: False)
       - `doctor_no_show_refund_percentage`: Decimal (default: 100.0)
    2. Implement `CancellationPolicyEngine`:
       - Evaluates time delta between `current_time` and `appointment.slot_start`.
       - If delta >= `free_cancellation_window_hours`: eligible for full refund.
       - If eligible: initiates Razorpay refund API (`POST /v1/payments/{payment_id}/refund`), records refund transaction, atomically transitions Appointment to `cancelled`, and releases slot back to open inventory.
       - If delta < window: marks Appointment `cancelled` with `refund_status = 'ineligible'` and retains fee per policy.
    3. Implement `POST /api/v1/appointments/{id}/cancel` endpoint accepting cancellation reason.
  </action>
  <verify>pytest backend/tests/test_cancellation_policy.py</verify>
</task>
