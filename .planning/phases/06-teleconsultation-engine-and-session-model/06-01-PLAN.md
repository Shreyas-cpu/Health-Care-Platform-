<objective>
Implement the native 1:1 Teleconsultation Engine and the 5-state session lifecycle layered directly on top of confirmed appointments, integrating LiveKit WebRTC token generation, in-call chat persistence, waiting room mechanics, and timeout handling.

Purpose: Teleconsultation is a native, first-class appointment type in the platform. It must interlock tightly with the appointment lifecycle, provide seamless web/mobile join flows, and enforce compliance consent before recording.
Output: Teleconsultation session models, LiveKit token generator, chat persistence service, session lifecycle API endpoints, and dual-state automated tests.
</objective>

<task type="lifecycle">
  <files>backend/app/services/teleconsultation_service.py, backend/app/api/v1/teleconsultation.py</files>
  <action>
    1. Implement session transition methods linked to Appointment Lifecycle:
       - `patient_enter_waiting_room`:
         - Precondition: Appointment is `confirmed`.
         - Session status -> `waiting_room`.
         - Appointment status -> `checked_in`.
         - Publish event to Redis Pub/Sub (`doctor_notified_patient_waiting`).
       - `doctor_start_session`:
         - Precondition: Session is `waiting_room` (or doctor ready).
         - Session status -> `live`.
         - Appointment status -> `in_consultation` for both parties simultaneously.
         - Publish event to Redis Pub/Sub (`session_live`).
       - `end_session`:
         - Session status -> `completed`.
         - Appointment status -> `completed` (unlocks prescription attachment).
         - Publish event to Redis Pub/Sub (`session_completed`).
    2. Implement timeout fail-safe:
       - If session in `waiting_room` exceeds 10 minutes without doctor, send high-priority alert.
       - If exceeds 20 minutes, session transitions to `cancelled` and patient is offered reschedule or automated refund.
    3. Compliance Gate (CMP-02):
       - If session recording is requested, verify both `doctor_recording_consent` and `patient_recording_consent` are True before initiating LiveKit recording egress.
  </action>
  <verify>pytest backend/tests/test_teleconsultation_lifecycle.py -k "test_dual_state"</verify>
</task>
