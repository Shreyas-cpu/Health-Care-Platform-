<objective>
Implement the Doctor Onboarding workflow on top of the Phase 01 Unified Identity foundation, and the 6-state administrative Doctor Verification Pipeline with S3 document uploads and immutable audit logging on every administrative mutation.

Purpose: Trust is the core product in healthcare. Unverified doctors must never appear in search; platform administrators need an auditable verification queue with strict reason tracking.
Output: Onboarding endpoints, S3 pre-signed upload handler, verification state machine service, admin queue APIs, and automated audit logging tests.
</objective>

<task type="logic">
  <files>backend/app/services/verification_state.py, backend/app/services/audit.py</files>
  <action>
    1. Implement 6-state verification transition rules:
       - submitted -> under_review
       - under_review -> info_requested, verified, rejected
       - info_requested -> submitted, under_review, rejected
       - verified -> suspended
       - suspended -> under_review, verified
       - rejected -> under_review (upon appeal)
    2. Enforce guard: Rejection requires non-empty `reason_text`.
    3. Enforce guard: Unverified doctors (`verification_status != 'verified'`) cannot have `listing_online == True`.
    4. Implement `record_audit_log` in `audit.py`: writes to `audit_logs` table inside the active DB transaction.
  </action>
  <verify>pytest backend/tests/test_verification_pipeline.py -k "test_state_transitions"</verify>
</task>
